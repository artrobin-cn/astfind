# 语义模型设置：远程 / 本地模式

> 状态：**v1 已实现**（2026-10-23）。设置页「语义模型」三态（关闭 / 远程 / 本地）可切换并持久化，
> 含探测、外发授权、本地启动指引。默认不变：旧配置仍按“第一个 Provider”解析，现有远程 WeMM-9B 用户零改动。
> 本地服务接入步骤见 [local-semantic-server.md](local-semantic-server.md)。本文保留设计推理与 v2 范围。

## 为什么需要

- 现在设置页的「AI 供应商」是给开发者/高级用户的多 Provider 列表：要手动填 endpoint、model、图片约定、批量，普通用户不知道选什么。
- 开源后用户可能只有本地模型，或只有远程端点；需要一个**明确的二选一/三选一**，而不是一张空表。
- 切换模型会改变向量维度与入库成本，必须有清晰的**当前模型、探测状态、迁移提示**。

## 目标

1. 设置页增加「语义模型」区块，默认展示当前模式与模型；用户可切换 **关闭 / 远程 / 本地**。
2. 远程模式：OpenAI 兼容端点 + 模型名 + 可选密钥引用 + 显式外发授权 + 「测试连接」。
3. 本地模式：本机回环端点（默认 `127.0.0.1:8098`）+ 模型名 + 「测试连接」+ 本地服务启动指引；零外发。
4. 切换前明确提示向量维度/profile 变化与重嵌入成本，不静默混用。
5. 探测失败/服务未启动时给出可执行错误，不阻塞文件名/OCR 搜索。

## 非目标（本阶段不做）

- 不在 App 内直接打包 Python/torch 运行时。
- 不做模型权重自动下载（5GB 级，许可证/磁盘/网络各有约束）。
- 不做 CoreML/Swift 原生推理（长期可做，工作量大）。
- 不自动把现有 4096 维远程向量迁移到 2048 维本地向量；迁移是显式动作。

## 当前架构事实

- `ProviderHub` 已支持多个 OpenAI 兼容 HTTP Provider（`providers.json`），含：
  - 文本 `input: "..."`；图片 `input: [{"image": "data:..."}]`；批量图片。
  - 能力探测（文本、1×1 图片、2 图批量）、失败分类、外发门（回环默认放行，远端需授权）。
- 设置页已有「AI 供应商（实验）」抽屉：添加/探测/移除/外发开关，但需要手填参数。
- `EmbeddingIndexer` 的 profile 由 provider/model/维度决定；不同维度不能混检索。
- 现有默认：远程 WeMM-9B，4096 维，profile `wemm-image-v1`；本地 WeMM-2B 为 2048 维（MRL 可 64–2048）。

## 建议的 UI

在设置页「统一搜索来源」抽屉内、现有 Provider 区块之前，增加：

```
语义模型
[ 关闭 ]  [ 远程 ]  [ 本地 ]

当前：远程 · WeMM-9B · 4096 维 · 已连接        [测试连接]

远程设置
  端点   https://…/v1/embeddings
  模型   wemm
  密钥引用（可选）
  [x] 允许把图片/查询发送到该远端（外发授权）

本地设置
  端点   http://127.0.0.1:8098/v1/embeddings
  模型   weemm-2b
  状态   未运行 / 已连接 · 2048 维
  [测试连接]  [如何启动本地服务…]
```

- 模式切换用 segmented picker，和现有设置风格一致；保留「AI 供应商」高级列表给多 Provider/自定义场景。
- 「测试连接」复用 `providers probe`，显示维度、图片/批量能力、延迟。
- 「如何启动本地服务…」打开一个说明页/文档，指向仓库的 `a0b-serve-next.py` 与模型下载/放置说明。
- 关闭语义模型 = 不注册图片 Provider，图片/视频语义通道隐藏；文件名/OCR/正文不受影响。

## 数据与迁移

- **Preset ID**：
  - `remote-wemm-9b`：4096 维，profile `wemm-image-v1`（现有）。
  - `local-wemm-2b`：2048 维，profile `wemm2b-image-v1`（MRL 可先 512/256）。
  - `local-gemma-2`：768 维，轻量/多语言备选。
- 切换时：
  1. 探测新 Provider 可用性与维度；
  2. 若 profile 不存在/维度变化，提示“需要为新模型建立向量；旧 profile 保留只读”；
  3. 新图用新 profile 入队；旧向量可按源分批重嵌入；
  4. 检索只查当前 profile，绝不把不同维度混算。
- 回退：本地服务健康检查失败时，可选“自动回退远程”或“只显示非语义结果”；默认安全侧是不静默回退，给用户提示。

## 本地运行时的两条路线

**v1（建议先做，工作量小）**
- App 不自带运行时；用户在仓库下载模型并按说明启动 `a0b-serve-next.py`（Python venv + MPS/CPU）。
- App 只配置 `http://127.0.0.1:8098/v1/embeddings`；健康检查/探测与远程完全同协议。
- 优点：复用已验证 Provider 通路；开源用户可选择自己跑；不把 5GB 模型塞进 App。
- 缺点：需要用户装 Python/模型，门槛高于“一键”。

**v2（后续，工作量大）**
- 原生 Swift/CoreML 推理或内置 sidecar；模型随 App/安装包分发或按需下载。
- 需要 CoreML 转换、量化、内存/ANE 优化、许可证合规、安装包体积与首启体验设计。
- 建议在 v1 验证用户需求与模型质量后再投入。

## 验收标准（v1 已全部达成）

- [x] 设置页「语义模型」三态可切换并持久化；重启后保持（`providers.json` 的 `semanticMode`，旧配置缺省=按 Provider 推断）。
- [x] 远程/本地「测试连接」显示维度、图片、批量能力；失败有可读分类。
- [x] 本地回环零外发；远程未授权时零请求（`SemanticModeTests` 钉住）；本地模式即便已授权外发也**只**选回环端点。
- [x] 切换 profile 有明确提示；不同模型/维度不会混检索——向量空间身份 = 模型 + 维度，签名变化派生新 profile，旧向量只读保留。
- [x] 本地服务未启动时，面板仍可文件名/OCR 搜索，语义通道显示不可用并给出启动指引。
- [x] 文档：远程/本地配置、模型准备、启动/停止、回退（[local-semantic-server.md](local-semantic-server.md)）。

### v1 实现要点（与提案的差异）

- **模式切换是两段式（2026-10-23 三次修订）**：点「关闭 / 远程 / 本地」只进入**待确认**——待选项淡色高亮，展开一张预览面板显示目标端点、模型、当前连通状态与外发授权情况，以及影响（当前索引暂停、向量不会自动重建）；用户点「切换到此模式」才写配置。预览面板里可以直接「先配置…」，只保存端点、不切换模式。切换本身**绝不弹建库确认**。
- **建库确认移到索引开关**：只有用户主动打开「图片与视频语义索引」时才弹「开始建立图片与视频索引？」（说明后台耗时与发送对象），取消则开关保持关闭、不启动泵。这样「换模型」和「花几小时重建」是两个独立决策，不会叠在一起压给用户。
- **设置页信息层级（2026-10-23 二次修订）**：三态选择器做成整行等分的大号控件（本区块唯一醒目元素）→ 当前状态单独一张卡，默认只显示「模型名 + 已连接 · N 维」，点开才是端点、测试连接、配置、外发授权 → 「图片与视频语义索引」是第二层抽屉，展开才显示开关、说明和入库进度，**进度轮询也只在展开时进行**（收起时设置页零额外数据库查询）。每段最多一句说明，长文只放抽屉/文档里。


- **切换模型不启动入库泵**：`setSemanticMode` 只写配置并停泵；建向量必须由用户显式打开「图片与视频语义索引」。
  全量重嵌是数小时级动作，绝不做静默副作用。
- **profile 身份的修正**：旧代码 profile id 恒为 `<providerId>-image-v1`，同 id 换模型/维度会让旧向量被误判
  “已入库”（新图永不补算）且检索维度不符被静默跳过。现由 `EmbeddingIndexer.resolveProfile` 按
  (provider, model, dimension) 解析：签名一致复用旧 id（现有 4096 维数据零迁移），不一致则派生带模型指纹的新 id。
- **本地模式的发送边界在数据层**：候选 Provider 按端点性质过滤，不依赖 UI 是否隐藏了某个开关。
